## 当前产品边界

真实 VibeVoice 输出的两场分析均已通过严格引用校验：7 月 562 段生成 54 项结果、109 处引用；8 月 254 段生成 15 项结果、42 处引用。两场各抽查 6 项，均发现至少 3 项需要人工语义校对，因此仍以建议形式展示，不自动更新正式项目记录。详细抽查与失败修复记录见 [分析验收](vllm-integration.md)。

宽泛跨会议问答最终完整返回：436 个候选片段、17 批及分层汇总，耗时 419.876 秒；22 处引用覆盖两场真实 VibeVoice 会议，全部 ID 和逐字引文校验通过。模型未遵守提示中的 6 条引用上限，结果未被强行截断。原验证脚本的 Node fetch 约 300 秒连接超时已修为显式 900 秒的 HTTP 请求；桌面 IPC 不受该脚本限制。该流程仍缺少问答进度与取消控件，长问题的等待体验需继续改善。

- 已取得用户指定的两场真实录音并接入私网 vLLM，Orca 浏览器操作记录见 [浏览器验收](orca-browser-verification.md)，真实模型语义评审结果见 [分析验收](vllm-integration.md)。Mac 及人工标注资料仍缺失，不能把所有阶段标记为完成。
- VibeVoice 权重及 Windows CUDA 依赖已安装并锁定版本，60 秒冒烟以及用户指定的两场完整录音转录均通过；分别得到 562 / 254 个有效片段，全部时间戳与音频哈希检查通过。完整配置、恢复耗时的统计边界见 [本机部署](local-deployment.md)。
- ASR 模型每次任务启动一个独立进程，因此取消可以释放推理进程，但模型加载开销较高；生产化可再改为长期模型进程。
- 去重采用保守规则，相似重叠片段可能保留；说话人只在会议内手工命名／合并。
- 检索采用本地字词匹配，不是语义向量检索；大段文本或过大的项目记录可能要求提高预算或缩小范围。语义判断仍需要人工核对。
- 工作台切换会议／页签前应保存校对，未保存状态有提示；当前没有多人协作或同步冲突处理。
- 备份恢复保留原库，会增加磁盘占用；程序不会自动删除原库。备份不能在录音或后台任务运行时执行。
- 个人试用包不承诺签名、公证和应用商店分发；没有购买算力或发布到外部服务。
