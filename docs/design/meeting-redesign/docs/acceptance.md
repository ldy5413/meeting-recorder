# 落地验收清单

## 视觉与交互

- 五个页面与设计基线一致；颜色、字体、页面比例、会议速览、侧栏与原文栏层次保持统一。
- 常用桌面窗口尺寸下无重叠、不可达控件或横向溢出；窄窗口重新排列，长标题与中文长文本正常换行。
- 悬停、焦点、选中和禁用状态都可辨认；普通文字对比度至少 4.5:1。
- 可用键盘操作导航、tabs、表单和弹窗；弹窗管理焦点，关闭后返回触发位置。
- 空数据、加载、失败、权限拒绝和恢复中状态都显示真实信息；不出现假进度、假完成或固定示例答案。

## 业务闭环

- 创建会议 → 录制或导入 → 转录 → 校对 → 分析 → 核对引用 → 确认待办／决策 → 项目追踪 → 导出可连贯完成。
- 姓名映射和 segment ID 保持一致；更新原文后旧分析与历史引用仍按现有版本机制处理。
- 周会的人员与子章节结构、讨论建议、关键画面、参数与单位可完整呈现，不能压成原型中的三条摘要。
- 音视频按真实协议加载；点击引用能定位正确会议、版本、文字或画面及时间。
- 任务排队、失败、重试、取消及录屏整理／恢复保持现有业务行为。
- 只有人工确认且通过已有校验的提案进入正式记录；缺少负责人或期限时不自动补造。
- 多项目、未归入项目、无选中会议、无音轨录像、长转录和多次分析都有明确行为。
- 配置、模板、原始文件入口、导出及完整备份恢复仍使用真实接口。
- 正式数据不落入原型的浏览器业务存储；密钥不进入渲染进程本地存储或交付文件。

## 检查命令

以原仓库当前脚本为准。核对时 `package.json` 与 `docs/development.md` 提供：

```sh
npm run format:check
npm test
npm run build
npm run test:e2e
```

依赖未安装时再使用仓库锁文件执行 `npm ci`。Electron 端到端测试需具备相应桌面环境，相关媒体测试按仓库说明准备 FFmpeg。已有检查的基线失败应记录、区分与本次改动的关系，而不是删除测试。

只改前端时，先完成适用的前端、共享类型和 Electron 回归检查。若实际修改 Python 服务，再按仓库开发说明运行其 lint、格式和测试。

## 真实设备与服务

使用独立测试库和明确提供的资料验证真实录音、转录、分析、问答与备份恢复。服务或设备不可用时列出未验证项，不用模拟数据宣称通过。不自动运行会访问内部会议或真实模型的历史脚本。

## 这份包已验证的内容

设计阶段的五个 HTML 原型通过了 108 项文档和 DOM 交互断言；会议库精修后做过一次渲染检查。它们证明原型的相应交互与文档结构，不等同于生产 Electron 回归、长时间录音、真实模型准确率或全量窗口尺寸验证。

交付包另外验证文件哈希、必需文件、页面间链接以及可独立读取的样式与脚本。最终应用验收仍需实施 agent 在原仓库完成。
