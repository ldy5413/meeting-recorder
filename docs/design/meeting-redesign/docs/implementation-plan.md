# 分批实施计划

以下阶段是同一项前端迁移工作的执行顺序，不要求每完成一小步都重新征求视觉方向。

## 0. 核对仓库与锁定边界

阅读当前仓库的规则与现有修改，核对交付包的关键源文件基线。确认五页设计、真实接口和已列出的差异。若仓库有更新，先调整映射，不用旧快照覆盖新工作。

交付：简短实施计划、组件拆分方案、需要保留的现有能力和有依据的差异说明。

## 1. 框架、会议库、会议详情

迁移全局布局、颜色、排版和控件。将原数据状态接入会议库、项目筛选、搜索、新建与编辑。会议速览由真实数据派生，无会议或无转录时展示合适的空态。

迁移纪要、转录、原文引用与媒体播放。保留姓名映射、版本选择、递归章节、人工纪要、会议背景、导出和原始文件入口。会议信息、分析和引用切换后不得残留上一场内容。

交付：可运行的 Electron 界面；能选择真实会议、阅读真实纪要、核对引用、校对并保存。

## 2. 录制与任务状态

为现有 `RecordPanel`、`Recorder`、`ScreenRecorder` 换用统一视觉。保留麦克风和系统音频、权限、设备选择、窗口选择、暂停、保存及异常恢复。将真实任务状态放入新布局，处理排队、进行、失败、取消和重试。

交付：现有录制与转录功能在新界面中仍可达、状态准确，不以原型的浏览器麦克风录音替代桌面录制。

## 3. 项目追踪、问答、模板与设置

迁移人工确认、正式记录和历史。实现独立导航所需的项目／会议范围状态。问答接入真实 evidence 和 coverage。设置和模板复用既有 IPC，保留内置模板、分析参数、密钥管理、图片许可及备份恢复。

交付：五页范围全部覆盖；原型超出当前能力的部分按差异清单处理，不出现模拟业务保存。

## 4. 回归与可评审交付

完成 `acceptance.md` 所列检查。提交或提供可评审变更及实际应用画面，说明已验证和未验证的范围。无需为视觉迁移自动升级 React / Electron、部署服务、制作发行版本或推送标签。

提交说明应围绕最终行为，至少包括：修改页面与组件、接入接口、验证结果、能力差异、硬件或服务限制。不要仅用“页面已完成”替代功能与数据一致性证据。
