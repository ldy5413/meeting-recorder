# 会议背景与分析模板

会议工作台的「背景与关键词」展示简短摘要，点击后在独立弹窗中编辑会议背景、逗号或换行分隔的关键词和默认分析要求。「生成分析」打开聚焦模板选择与本次补充要求的弹窗，保存后启动任务。背景修改不自动重转录，再次转录才影响识别。

侧栏提供三个独立入口：「分析模板」「项目默认设置」「服务与备份」。模板页采用列表与预览／编辑双栏，内置项目进度会和每周周会为只读，可复制为自定义模板；自定义模板支持创建、编辑、复制和删除确认。项目默认设置仅复制到新会议，已有会议可手动重新载入。删除仍被选择的模板后，需要重新选择模板；历史分析保留原模板快照。服务页仅配置服务连接及备份恢复。

## 数据与证据

- 新增请求：`meeting.context`、`project.context`、`meeting.reloadDefaults`、`template.save`、`template.delete`。Electron 与开发桥复用相同分发和校验。
- `Meeting.context` / `Project.context` 保存配置；缺失时使用空背景、空关键词和项目进度会模板。自定义模板存于 SQLite `meta.analysisTemplates`，随现有备份恢复。
- 每个新任务保存背景、关键词、模板内容、补充要求、校对姓名和项目记录快照。重试沿用原快照；分析结果独立保存快照及 `sections`。旧分析没有章节时保留平铺展示和导出。
- ASR `/jobs` 接受 multipart `context_info`，持久化到任务，并参与每个窗口的缓存指纹。同一幂等键、不同背景返回 HTTP 409。普通窗口及二分重试窗口使用同一背景。
- 分批提取和事实审核后，对通过条目统一去重和组织章节。不同人员的相同措辞不会合并，同一已校对人员的重复事实合并引用。章节只能引用条目索引，索引完整性及标题/人员归属分别校验；不允许通过模板取消事实审核。
- 人工姓名映射可以核验明确的第一人称行动承诺，仍需语义审核确认本人承担任务。周会中未命名的单一发言来源可按编号分组；无法确认发言来源或人员归属的内容列为未确认人员。
- 页面、人工纪要初始内容和 Markdown 共用章节及条目引用。分析面板可导出当前选择的历史版本；工作台顶部导出最新版本。人工编辑内容仍为单独保存的文本。旧版本引用继续通过原有历史转录解析回听。
- 背景、模板、记录和输出均受上下文预算限制，超限任务明确失败，不静默裁剪。长会议按预算分批组织并审核章节，再合并同名章节及原条目索引；每批仍须完整覆盖其审核条目。

## 每周周会的人员与栏目

0.1.9 起，内置「每周周会」让模型为每条已审核内容选择人员和「本周进展」「下周计划」「阻塞与协助事项」之一，由程序生成两层章节：人员标题不直接挂条目，子栏目引用对应条目，空栏目省略，同名人员及栏目跨批次合并。模型输出 `assignments:[{index,person,column}]`，最终保存和导出的格式仍为 `sections`，历史分析兼容。

人员选项来自任务保存的人工姓名映射、已审核负责人的姓名，以及条目实际引用的未命名说话人编号。已有确认姓名时使用姓名；没有姓名且引用只来自一个可区分的说话人时，按 `speaker-1`、`speaker-2` 等原始编号分组。匿名章节表示发言来源，不表示该人承担或完成了所述工作，也不会把编号填入待办负责人。

程序依据条目引用的片段 ID 核对说话人，不能由模型自由编造分组。带猜测姓名的编号或其他未确认姓名会移除猜测部分，并按实际引用来源归组；不会按猜测的姓名匹配到其他已确认人员。多人来源、未能区分的声音以及纯画面内容无法确认归属时，放入「未确认人员」。原条目、引用和负责人保持不变，原始归类、调整后的分组和独立章节审核输出保留在本地审计中。

每批索引必须全部覆盖且各出现一次，遗漏、重复、越界或不支持的栏目仍会反馈重试。程序生成层级后继续独立审核章节语义及人员归属，错误归属仍会失败，不通过改名将工作归给其他已确认人员。

已有任务如果停在「按模板组织章节」，升级后可直接重试，复用已完成的语音与画面分析批次。旧周会模板快照也支持按匿名编号分组；重试仍沿用原姓名快照，若修改姓名映射并保存为新转录版本，应新建分析任务以使用新姓名。
