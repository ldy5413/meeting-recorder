# 应用内录屏

第二阶段先支持 Windows。新建会议后点击「开始录音 / 录屏」，选择「录音 + 屏幕」，再选择具体窗口或显示器。检查预览和音量后开始保存；可暂停、继续、结束录制。预览不合适时可点击「重新选择设备或画面」。

本机需要 FFmpeg 和 FFprobe，可通过 PATH 或 `FFMPEG` / `FFPROBE` 配置。设备检查时会验证这两项依赖。其他系统仍可导入已有录像，应用内录屏的 macOS 适配尚未完成。

## 声音与画面

- 麦克风和系统声音分别开关、分别显示电平。两项都关闭时保存无音轨录像，仍能使用画面分析。
- 系统声音包含电脑播放的其他声音。选择窗口只限制画面范围，不会隔离该窗口的声音。
- 录制目标为最高 1920×1080、15 fps，实际尺寸由来源和系统协商确定。输出为 WebM，视频目标码率 3 Mbps，音频目标码率 128 kbps；实际文件大小随内容变化。
- 录屏模式通过同一媒体流编码画面与混合声音；转录从最终录像提取音轨，使用最终媒体时间轴。纯录音模式继续保存独立的麦克风、系统声音和混合 WAV。
- 录制过程中持续显示所选来源。窗口关闭或采集设备断开时停止并保存，避免意外切到其他来源。暂停不计入最终录像时长。

## 保存与恢复

编码数据通常每秒交给主进程，按序号写盘、`fsync`，再把确认字节数和下一个序号保存到 SQLite。分块回调不是精确时钟，程序不根据回调次数计算音画时间。

停止时先等待最后的数据块，再整理容器时长与定位信息，并检查首尾附近的画面解码。界面显示「正在保存与整理」，完成后才显示为已保存。画面、转录与引用沿用同一录像时间轴。

在会议顶部点击「原始文件」，可查看录音／录像的绝对路径、文件大小，并在资源管理器中定位。Windows 默认保存在 `%APPDATA%/meeting-recorder/library/audio`，界面以当前实际会议库为准。纯录音会列出已有的混合、麦克风和系统声音 WAV；录屏显示原始 WebM，尚未整理完成时显示待整理数据的位置。文件缺失时仍保留预期路径提示。

异常退出后，启动时按数据库记录的确认位置恢复。尚未写盘的尾部无法恢复；恢复提示会给出可播放时长，需核对结束位置。若缺少工具或媒体整理失败，保留原始数据，并提供「重试整理录像」。关闭应用时可选择保存并退出；编码器无响应时保存确认写入的部分。

待写入队列和单块大小有上限，写入跟不上时停止录制；单场录像文件上限为 24 GB。后续图文分析仍有 6 小时、600 张自动画面的限制，长会议应分段。

完整备份升级为格式 3，包含尚待恢复的录像、最终媒体、结构化参数及历史引用；可读取格式 1、2、3。旧版应用不能恢复格式 3。

## 分析与隐私

录制只写入本地会议库。转录和画面分析仍由用户触发，发送范围遵循服务设置。录屏本身不会把媒体发送到模型服务。

保存后复用已有的关键画面、转录、分析、引用回放、导出和备份流程。摄像头、多路画面、实时图文总结不在本阶段范围内。

## 验证

自动测试包含真实窗口选择、暂停和继续、保存和定位、来源关闭、正常退出、强制结束整个测试进程树后的重启恢复，以及写入失败和待恢复数据备份。同步测试用同一时钟生成闪光和提示音，验证暂停前后的对齐。

显式长时间验证使用专用测试窗口及合成麦克风，不读取其他应用的声音：

```powershell
npm run build
npx tsx scripts/validate-screen-recording.ts --seconds=7200 --output=.local/screen-soak
```

脚本定期记录确认写入的字节数、数据块数量和进程内存；结束后检查时长、音轨和首尾音画标记的相对漂移。短测试的音画标记来自同一时钟，长测试使用两个独立周期标记衡量漂移变化，不把它们的初始相位差当作录制延迟。实际录制结果及本轮验收记录只保存在 `.local/`。

可用 `--width=1920 --height=1080` 调整专用测试窗口尺寸，用 `--executable=安装包解包目录/Meeting Recorder.exe` 验证打包后的程序。脚本只采集自己创建的窗口 ID，支持与其他测试并行；结果会记录实际媒体尺寸。

录制元数据保存为 `recording.json`，可在原命令后加 `--verify-only` 重新解码已保存的录像。标记检测分辨率为 50 毫秒，以整数采样格比较首尾漂移，验收上限包含 250 毫秒边界；该指标不能代表所有瞬间的音画误差。

2026-09-07 的 Windows 本机验证中，两小时录制保存了 7200.598 秒、782×478 的录像，首尾相对漂移为 250 毫秒，位于验收上限。打包程序另连续录制 20 分钟，实际尺寸 1918×1080、时长 1200.585 秒，首尾相对漂移为 100 毫秒；最终安装包的独立 30 秒录制也已通过。两小时结果不代表高清压力测试；测试均使用合成音频，尚未覆盖各会议软件实际系统音频及不同硬件组合。

技术依据：[Electron desktopCapturer](https://www.electronjs.org/docs/latest/api/desktop-capturer)、[Electron session](https://www.electronjs.org/docs/latest/api/session#sessetdisplaymediarequesthandlerhandler-opts)、[MediaRecorder.start](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/start)、[MediaStream Recording API](https://developer.mozilla.org/en-US/docs/Web/API/MediaStream_Recording_API)。
