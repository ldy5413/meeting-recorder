# 跨 chunk 说话人统一

0.1.3 在 VibeVoice 转录后增加整场会议的声纹匹配。文字识别仍可用小窗口适配显存；说话人身份不再随窗口重新编号。失败重试拆出的子窗口也参与同一轮匹配。

## 部署与使用

在已经安装 PyTorch、torchaudio 和 FFmpeg 的转录服务环境中：

```powershell
.\.venv\Scripts\python.exe -m pip install -r service/requirements-inference.txt
.\.venv\Scripts\python.exe scripts/download-speaker-model.py
powershell -NoProfile -File scripts/start-asr.ps1
```

先停止旧的空闲转录服务，再运行启动脚本。新会议自动执行匹配；已完成的会议在原文页点击「自动统一说话人」。有未保存的校对时先保存。修复会生成新转录版本，保留原文、时间戳、引用 ID 和已确认姓名；旧版本保留，既有分析按版本规则标记过期。新桌面端通过 `/health` 能力字段检查服务版本，旧服务会提示升级，避免意外重跑 ASR。

原文页可以填写「实际发言人数（可选）」，留空仍全自动。人数用于帮助合并已有声纹支持的相近分组，不会强制合并不同姓名或明显不同的声音，也不会凭空补足人数。没有发言的参会者无需计入。界面将识别到的说话人数与待确认发言段数分开提示。

点击说话人标签，或展开「待确认发言」后点击对应标签，会自动翻到该标签时间最早的发言，滚动定位并高亮；姓名输入框和合并下拉框保持独立。定位支持跨页及未保存的校对，不自动播放录音；点击该段时间戳即可回听。

独立 JSON 也可修复，输入支持 `{"segments":[...],"speakers":{...}}` 或片段数组：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/repair-speakers.py --audio audio.mp4 --transcript transcript.json --output .local/repaired/transcript.json
```

脚本输出到独立文件，不能覆盖输入文件。桌面安装包不包含 Python 环境或模型。
已知人数时可追加 `--expected-speakers 6`；服务和桌面端都需要更新，旧服务不支持人数参数时会在上传前提示。

## 模型与匹配规则

使用 [WeSpeaker 官方 ResNet34-LM 声纹模型](https://huggingface.co/Wespeaker/wespeaker-voxceleb-resnet34-LM)，许可为 CC-BY-4.0，归属 WeSpeaker 项目；模型文件保持原样。固定仓库版本 `f0c48c298fd835726c27956a5d617bad7115627e`，ONNX 文件大小 26,530,309 字节，SHA-256 为 `7bb2f06e9df17cdf1ef14ee8a15ab08ed28e8d0ef5054ee135741560df2ec068`。下载脚本及每次处理都会检查哈希。

前端参数遵循 [官方 ONNX 推理示例](https://github.com/wenet-e2e/wespeaker/blob/master/wespeaker/bin/infer_onnx.py)：16 kHz 单声道、80 维 Kaldi filterbank、25 ms Hamming 窗、10 ms 帧移及逐样本均值归一化。ONNX Runtime 使用 CPU，不额外占用 CUDA 显存。下载模型不携带会议内容；录音和声纹仅在用户配置的转录服务上处理，声纹不跨会议建立身份库。

- 算法 v2 按发言片段提取声纹，每段最多取 8 秒，边界留出 0.1 秒。优先减去其他标签标注的重叠区间；只剩重叠声音时，仅允许用于匹配已有声音，不参与建立声纹。0.8–2 秒的短片段也可参与匹配，更短的片段不独立提取声纹。
- 先用至少 2 秒的干净片段做 average-link 聚类，再选择至少 3 次发言、累计至少 8 秒的重复声音作为稳定声纹。已确认姓名保留独立约束；没有任何稳定声纹的短录音回退到已有候选组。长录音最多使用 1200 段建立声纹，按原标签轮流选取较长片段，其他片段仍参与匹配。
- 默认基准阈值为 0.65，可用 `MEETING_SPEAKER_THRESHOLD` 调整。初始聚类阈值为 `max(0.45, 基准阈值 - 0.1)`，稳定声纹按基准阈值去重。逐段匹配阈值为 `max(0.5, 基准阈值 - 0.15)`，并要求第一候选领先第二候选至少 0.1；短句及重叠片段至少需要 0.6。所有分数均为启发式余弦相似度，不代表概率或准确率。
- 匹配阶段的声纹保持固定，低质量片段不会反过来改变声纹并导致连锁误合并。同一旧标签中混入不同人的发言可以分别归组。匹配不明确时，仅当旧标签已有至少 3 次一致匹配、占有效投票至少 90% 且占原标签发言至少 50%，才沿用该标签的归属；审计中单独标为 `retained_label`，不冒充直接声纹匹配。
- 已知人数只会适度放宽稳定声纹之间的合并条件，底线为 `max(0.5, 基准阈值 - 0.15)`，始终保留姓名冲突约束。证据不足时允许实际分组数与指定人数不符，记录 `count_matches=false`，不把人数相等当作正确率验证。
- 不同已确认姓名不能合并。没有足够清晰语音的标签显示「待确认」，不猜姓名；`[Silence]` 等明确的非语音标记保留原片段，显示为「静音 / 非语音」，不计入人数。非语音标记以外的 `unknown` 发言仍按真实语音处理。
- 声纹缓存使用音频 SHA-256、模型哈希、算法版本及取样区间作为键，逐片段持久化，失败重试可恢复。姓名及人数调整可复用同一缓存。逐段映射 `segment_mapping`、第一候选得分和领先差距、直接匹配／沿用旧标签／待确认的处理方式写入 `speaker-resolution.json`，最终服务响应也包含这些信息。旧 `mapping` 仅包含没有发生拆分的原标签。

API 沿用 `POST /jobs`，multipart 字段为 `task=speakers`、`segments`（JSON 数组）、`speaker_names`（JSON 对象），以及可选 `expected_speakers`（1–50 的整数）。该任务只探测音频并匹配声纹，不构造 VibeVoice；输入及人数包含在幂等键冲突检查中。原有转录请求不需新增字段。`/health` 保持 `speaker_resolution_version=1` 协议兼容，新增 `speaker_algorithm_version=2` 和 `speaker_count_hint=true`。

## 2026-09-15 会议回放验证（算法 v2）

用户指定的 `20260915` 会议长约 72.9 分钟，包含 524 个片段。旧结果为 13 个声纹分组、8 个待确认标签（共 21 项），另有 17 段非语音。独立本地回放得到 **6 个声纹分组、9 段待确认发言**（分属 6 个旧标签），17 段非语音保持不变。

留空人数与指定 6 人得到完全相同的逐段归组。507 段语音中，439 段直接匹配声纹，59 段根据一致的旧标签保留归属，9 段待确认。首次处理约 80.6 秒，使用已有 CPU 模型，没有重新转录。524 个片段的 ID、文字及起止时间逐项一致；正式会议及历史版本保持原样，副本和结果仅存放于 Git 忽略的 `.local/speaker-review-20260915/`。

另外从初次 ASR 缓存重建原始的 73 个分段标签，模拟新转录后的首次统一，同样全自动得到 6 个稳定声纹分组；此路径因原标签更加零碎，有 21 段发言待确认（12 个待确认标签），50 段沿用一致旧标签。待确认段数与人数分开统计，不能混用首次统一和当前版本修复的结果。

这是单场会议的分组验证，未进行逐段人工标注，不能据此声称识别准确率。极短发言、重叠语音、原转录时间边界不准仍可能需要回听；自动分组不会确认真实姓名。

## 未确认姓名时生成纪要

没有填写姓名也可以分析会议。`speaker-2`、`unknown`、`待确认 1` 等仅表示匿名说话人，不是已确认负责人。0.1.8 会在逐字引文校验和事实审核前，将模型误填的这类 `owner` 设为 `null`，保留行动内容、期限及发言引用；不同匿名说话人的待办仍分别保留。原始模型输出和调整记录写入本地分析审计，便于排查。

真实姓名仍须有原文明示，或来自对应片段的人工姓名映射且引用包含本人承担该任务的承诺。无法验证的真实姓名、改写或拼接的引文仍会被拒绝；未确认负责人也不免除行动和期限的事实审核。

原任务若因匿名负责人失败，升级后点击「重试」即可继续已有分析批次，无需重新转录或先填写姓名。若修改姓名映射并保存校对，会产生新转录版本，应重新分析以使用更新后的身份信息。

## 2026-09-06 本机实测

指定的匿名样本 A 录音长 3303.62 秒。对截图所示转录的 563 个片段进行声纹处理，37 个原标签归为 **2 组有声纹支持的说话人、1 个待确认标签**；待确认项仅一句约 1.13 秒的短发言。另外 75 个 `[Silence]` 片段来自 12 个原标签，已排除人数统计。首次声纹提取及初轮匹配耗时约 43.22 秒；后续聚类修正复用声纹缓存，不包含重新转录。

随后通过重启后的实际 `/jobs` 接口独立验证，端到端耗时 35.22 秒，得到相同的 2 组说话人及 1 个待确认标签；该任务未产生 ASR chunk 缓存。原音频与应用导入副本 SHA-256 一致。应用中的该场会议从 v1 保存为 v2，563 个片段 ID、文本及时间戳逐项保持一致；修复前另有 SQLite 快照。私有结果位于 `.local/speaker-validation/`，原始服务声纹和映射位于对应 `.local/asr-data/` 任务目录，均不纳入 Git。

本机 Windows 安装包：`release/speaker-fix-0.1.3-final/Meeting Recorder Setup 0.1.3.exe`。桌面验证使用隔离库，实际会议截图中的说话人栏只有两个声纹分组和一个待确认项。

上述历史实测使用算法 v1，仅匹配整个标签，不能修复同一个旧标签内混入不同人的问题。算法 v2 改为逐段匹配，但多人同时讲话、远场噪音、极短发言仍可能需要回听。姓名仍由用户确认，不从背景名单或文字内容猜测身份。
