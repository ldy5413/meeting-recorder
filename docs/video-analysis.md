# 录像分析

支持导入 MP4 / WebM，保留原始录像、在本机提取音轨和关键画面，再结合转录生成带发言与画面引用的纪要。第二阶段新增 [Windows 应用内录屏](screen-recording.md)，摄像头采集仍属于后续阶段。

## 使用

1. 安装 FFmpeg 和 FFprobe 并加入 PATH；也可分别设置 `FFMPEG`、`FFPROBE` 为可执行文件绝对路径。桌面安装包不捆绑这些工具。
2. 在新会议点击「导入录音 / 录像」。有音轨时，点击「分说话人转录」；无音轨录像可以直接分析展示内容。
3. 在「服务与备份」配置分析服务，确认画面发送范围。图片模型名称留空时使用分析模型，也可指定同一服务上的另一个图片模型。「测试图片连接」使用合成图片，不含会议内容；连接成功不代表实际识别准确率。
4. 「录像与画面」可提取、识别和核对截图，排除无关画面；播放到关键时刻后可以补充当前截图，再识别未完成的画面。
5. 「生成分析」默认勾选结合画面；也可取消勾选，只生成转录分析。勾选后自动完成尚未处理的画面，再进行分析和原图核对。
6. 纪要的「画面」引用打开对应截图并定位播放器；点击截图可查看原始分辨率。排除画面后，旧分析仍可回看，新的项目记录确认需要重新生成分析。
7. 会议顶部的「原始文件」显示录像在会议库中的实际位置与大小，可点击「在文件夹中显示」定位文件。导入录像显示库内副本；录屏显示保存后的原始 WebM。

## 输出截断与思考模式

「上下文预算」限制输入和输出的总额度；把它调大并不会自动改变每次请求的输出上限。0.1.5 起，画面识别首次请求最多输出 8192 tokens，其他分析请求通常从 4096 开始。在「服务与备份」可设置「最大输出长度」，默认 16384，上限 32768。实际请求还受剩余上下文预算限制，服务本身也可能有更低的限制。

收到 `finish_reason: length` 后，程序保留响应审计，将输出额度提高到配置的上限，并要求重新生成完整、紧凑且保留参数条件的 JSON；每次调用最多重试一次，仍受剩余上下文预算限制。不续写或接受截断结果。错误会给出实际额度及调整建议；已完成的画面独立保存，任务失败后点击「重试」继续。进度同时显示整批位置和本次位置，例如「识别关键画面 51/194（本次 1/144）」。

Qwen 的思考可能占用输出额度，但截断也可能是密集表格的正式答案过长。[Qwen3.8 模型说明](https://huggingface.co/Qwen/Qwen3.8-27B) 与 [vLLM 思考输出文档](https://docs.vllm.ai/en/latest/features/reasoning_outputs/) 说明了思考开关与输出预算的关系。使用支持该开关的 vLLM 服务时，可在「Qwen 思考模式（vLLM）」选择关闭或开启；程序发送 `chat_template_kwargs.enable_thinking`。默认「跟随服务设置」不发送该字段，其他兼容接口应保留默认。隐藏思考文本不等于停止生成思考。

修改输出长度或思考设置后可重试失败任务，保留此前完成的观察；若需要用新思考设置检查某张已完成的画面，使用「重新识别此画面」。思考设置参与新观察的缓存来源匹配。扩大额度只解决输出完整性，不能保证表格行列、数字或语义正确，仍需核对原图。

## 画面引用校验

0.1.7 起，生成画面候选时，将观察原文按行和长度划为有编号的 `evidenceSources`，每个片段都保留原文字面内容。模型输出 `evidence:[{frameId,sourceId}]`，程序只在当前画面的证据目录中查找编号并填入完整 `quote`。跨行证据可选择多个片段，不需要模型重复抄写 Markdown、公式和代码。选中参数片段时自动带上对应 `parameterRefs`，保留完整单位及条件。

不存在的编号、其他画面的编号组合或同时附带改写 quote 的引用会拒绝并反馈重试。编号匹配后继续做严格引用校验和原图语义审核，不表示结论已经成立；仍可因无事实支持或重复被剔除。原始模型输出、所选编号与实际引文保存到 `quoteBindings` 审计和检查点中。历史证据格式保持 `{frameId,quote}`，旧任务的已完成分组可直接续用。

0.1.6 起，画面观察与模型引文只差 Markdown `**加粗标记**` 时，会在引用的同一张画面内寻找唯一匹配，将引文还原为原文的连续子串，再执行原有的严格校验和原图事实审核。例如观察为 `**压力**：80 kPa`，模型引用 `压力：80 kPa` 时，保存的证据会还原为 `**压力**：80 kPa`。

这项处理不修改观察文字、转录或旧分析，不进行近似匹配；数值、单位、否定词、标点、空格不一致、跨画面引用或有多个匹配位置时不会自动修复。代码和疑似运算符中的星号保留。原始模型输出与引文还原记录分别保存到分析审计和检查点中，事实审核仍可拒绝没有证据支持的条目。

升级后可直接重试原失败任务，已识别的画面和已审核的分组会继续复用，无需重新转录。

## 数据与处理

- 原始录像复制到本地会议库。新导入录像在桌面端提取 16 kHz 单声道 WAV，再发送到配置的转录服务；分析服务接收选中截图、转录、模型观察和原有分析上下文。排除画面只影响后续请求，不撤回此前已发送内容。
- 本地以每 2 秒一帧、160×90 灰度图扫描变化；保留显著变化，最短间隔 4 秒，90 秒补充一次。候选截图按源分辨率保存为 JPEG。第一阶段最多 6 小时、600 张自动截图；超过上限明确提示分段，不静默丢掉后半段。尚未实现专门的共享区域裁剪、连续动作理解或逐帧覆盖。
- 截图时刻与转录使用录像时间轴。先对完整转录建立语音纪要，再逐组补充画面信息，每组一张截图，兼容每次请求仅允许一张图片的服务。画面请求包含前后 15 秒发言，以及预算内相关的已审核条目。截图的结束时间是采样区间边界，并不保证图像在整个区间内未变化。
- 识别时自动排除仅有参会者头像或空白的画面；排除结果可在时间线中查看。没有对应画面的发言仍单独分析，不把之前的幻灯片延伸到后续无关讨论。
- 每张观察独立落库，字段格式错误反馈重试一次，任务失败可继续未完成画面。图文分析按顺序补充，复用已完成的语音与画面检查点；每项同时审核事实支持与新增性，缺少必需判断时校验反馈重试，不默认通过。无新增条目时跳过不必要的原图审核请求。原始响应保留审计，画面保存模型与服务来源。
- 画面证据使用 `{frameId, quote}`，发言沿用 `{segmentId, quote}`；不能混用。画面 quote 引用观察文字或结构化参数的完整表述，不冒充人工转录或已核实 OCR。参数保存对象、指标、数值、单位和条件；条目引用参数索引后，完整参数及相应引文会自动加入条目，展示、导出与历史快照使用同一份内容。涉及画面的结论还需通过带原始截图的模型审核。
- 画面候选提取与新增性审核分开：先根据当前画面观察提取要点，再与既有纪要逐项比较并核对原图。比较保留已审核条目的完整文字与参数条件，移除重复引文和标识开销，优先选择包含相同参数或相邻发言的条目。参数引用缺少画面证据时反馈纠正；只有纯语音且未引用画面参数的候选会排除，并保留审计。比较仍受上下文预算和模型判断限制，不保证消除所有语义重复。表格脚注中的另一测量值单独保存，不与原数值混为同一条件；图表计数须排除空白占位格。
- 仅凭画面不能确立正式决策、行动承诺、负责人、期限或完成状态。语义审核仍可能出错，需要人工查看原图和发言。
- 长会议的已审核条目分批组织章节，明确提供合法索引，审核后合并同名章节；不把整场会议的全部条目一次性送入模型。输出 JSON 截断或格式错误保留审计并反馈重试一次，不接受残缺结果。
- 分析保存画面版本及观察快照。截图选择变化会使相关分析过期；历史画面引用保留。SRT 只含发言，Markdown 随附引用截图到同名 `.assets` 目录；分享 Markdown 时需保留该目录。
- 完整备份格式为 3，包含音视频、待恢复录像、提取音轨、关键画面、参数和历史引用。新版可恢复格式 1、2、3；旧版应用不能恢复格式 3。
- 有据问答当前仍只检索转录；画面检索不在本阶段范围。

## 验证

第二阶段还增加了相同图片字节与相同服务配置下的识别缓存。「重新识别此画面」跳过缓存，保留旧分析快照并使当前分析过期；排除的画面需先重新加入。点击旧分析的画面引用会使用该次分析的观察与参数快照，可切换查看当前观察。旧观察缺少结构化参数时，首次分析会重新读取原图。缓存只复用完全相同的图片，没有启用可能吞掉小数值变化的近似去重或共享区域自动裁剪。

第二阶段内部录像对照可显式运行 `npx tsx scripts/validate-video-phase2.ts --index=1` 和 `--index=2`。它从第一阶段验证库读取原视频、截图和转录，建立独立的 `.local/video-phase2/` 测试库；结果与历史基线按会议 ID 对应，不能仅凭脚本中的数字编号对应录像。默认复用完整结果；添加 `--rerun` 会保留旧分析并创建新分析，失败时可续跑。

自动测试覆盖实际媒体解码、场景变化截图、音轨提取、音画引用隔离、原图核对请求、失败重试、历史引用及备份恢复。桌面测试覆盖录像导入、识别、分析、引用播放跳转、原图查看与排除后过期提示。

根目录内部视频已加入 Git 忽略规则。实际视频、转录、截图、模型输出和对比纪要只保存在本机 `.local/` 中；不进入仓库。

显式运行真实服务测试：

```powershell
.\.venv\Scripts\python.exe scripts/video-asr-validation.py
npx tsx scripts/validate-videos.ts --prepare
npx tsx scripts/validate-videos.ts
powershell -NoProfile -File scripts/review-videos.ps1
```

前两个命令可同时运行，分别调用已配置的本机转录服务与内网图片模型；最后的完整分析在转录完成后运行。脚本复用已完成的任务与画面，分别保留纯转录和结合画面的分析版本。`--index=1` / `--index=2` 可单独验证对应视频。不要在任务运行时打开同一测试库的桌面应用（应用启动会恢复未完成任务）；等测试结束后再运行查看脚本。

### 第一阶段自动与真实媒体验证（2026-09-07）

- TypeScript 单元／集成测试：33 项通过；桌面端到端：6 项通过；生产构建与格式检查通过。
- Python 服务回归：16 项通过、1 项因系统 Python 缺少推理依赖跳过；另在推理虚拟环境执行该项，1 项通过。Ruff 检查通过。
- 两段内部录像时长分别为 3693.888 秒和 3812.416 秒，均为 1920×1080。完整音轨由生产提取函数解码为 16 kHz 单声道 WAV，与原视频时长一致。
- 完整转录分别生成 329、251 个发言片段，每段录像的 14 个转录窗口均完成。校验输入文件、导入副本与实际送入本机转录服务的文件 SHA-256 一致。
- 自动提取 103、135 张关键画面；经分类分别保留 102、56 张有内容的画面。后者大量仅有参会者网格的画面被排除，相关发言仍保留。

两段完整图文分析均已完成。纯语音版本分别有 62、60 条条目；图文版本分别有 284、194 条，其中 67、58 条带画面引用，引用到 64、45 张截图。两种模式分组粒度不同，这些数字反映输出规模，不能作为准确率或召回率指标。

对照入口保存在本机 `.local/video-validation/comparison.md`，链接到四份完整纪要。原图人工抽查记录见同目录 `manual-review.md`；`report.json` 保留数量统计。

人工抽查发现：首轮观察曾把空图格计入子图数量，生成条目时未采用该数量；另有参数摘要省略了原图中的限定条件，而模型审核仍予通过。因此画面观察和摘要均保留原图引用，重要参数需要人工核对。图文条目增加也可能伴随重复，目前没有量化整体质量提升。

### 第二阶段验证（2026-09-07）

TypeScript 单元／集成测试 40 项通过，桌面完整回归 11 项通过；随后对参数表、重新识别和历史快照引用的桌面用例另行复验通过。生产构建、格式检查和显式验证脚本的类型检查通过。Windows 连续两小时录屏、20 分钟高清录屏及打包程序验证的范围和结果见 [应用内录屏](screen-recording.md#验证)。

真实资料抽查验证了结构化参数的限定条件可以贯穿观察、纪要、导出和历史引用；同时仍发现专业术语误译、图格计数错误和低价值重复描述。自动检查能阻止不存在的引用，并向模型反馈合法参数索引范围；模型审核通过仍不代表内容准确。内部对照和人工抽查记录保存在 `.local/phase2-acceptance.md`，尚未建立整段录像的完整人工事实标注或量化整体准确率。
