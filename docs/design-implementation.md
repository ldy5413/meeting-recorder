## 核对与实施顺序

核对时项目 HEAD 为 `4d7c7e1a47f68d2ab1dd6f3010d5bc04a65624cf`，交付包中 15 个关键源文件的哈希全部与工作区一致。工作区原有周会章节、说话人、版本及测试改动保留；本次没有修改 Electron 业务、共享请求类型、数据库、采集类、Python 服务或依赖版本。

先迁移应用框架、会议库及会议详情，再迁移录制与任务呈现、项目追踪、问答、模板和设置。原始交付包保持字节不变，单独排除格式化，并继续通过包内完整性校验。

## 页面和数据接入

| 范围       | 实现与真实接入                                                                                                                                                                                                                                                                |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 应用框架   | `AppShell.tsx` 提供全局导航、项目入口、面包屑和窄窗口导航。会议、项目与页面使用独立前端状态；录制横幅在全局导航后仍可操作。`state` 定期刷新，写入后立即刷新，旧读取结果不能覆盖更新的读取。                                                                                   |
| 会议库     | `MeetingLibrary.tsx` 使用真实会议生成石墨色速览、时长及分段条。支持名称搜索、全部／已有转录／待处理筛选、项目及未归入项目入口；每批显示 50 场。新建和导入沿用 `meeting.create/update`、`audio.import`，日期转换为带时区的 ISO 时间。                                          |
| 会议详情   | 保留纪要、递归人员与子章节、讨论建议、分析版本、人工纪要、原始模型输出、背景关键词、姓名映射、自动统一说话人、转录导入及校对。原文每页 60 段；编辑与保存仍提交完整 segments，并保留 segment ID。                                                                              |
| 引用和媒体 | `EvidencePanel.tsx` 并列展示原文，可收起；每页 20 段。点击证据仍调用 `evidence.resolve`，历史正文单独标明版本，画面保留原分析快照。会议及分析版本切换清除旧引用。时间戳可定位长原文和真实媒体。保留 `meeting://audio/…`、`meeting://frames/…`、`VideoPanel` 与 `MediaFiles`。 |
| 录制及任务 | 保留 `RecordPanel`、`Recorder`、`ScreenRecorder` 的设备、权限、系统音频、窗口选择、暂停继续和停止保存链路。新界面展示真实 job 状态及错误，调用原有重试、取消和录像恢复请求。                                                                                                  |
| 项目追踪   | `ProjectTracking.tsx` 从各项目会议最新且原文／画面版本有效的分析中汇集提案；已确认索引及已变化的目标记录版本不重新混入。每项保留 meeting ID、analysis ID、claim index。核对弹窗调用现有 `proposal.accept`，保存后刷新正式记录和历史。最终事实校验与事务仍由原业务层负责。     |
| 有据问答   | `MeetingAsk.tsx` 支持独立选择会议或项目、日期及问题，调用真实 `ask` 并展示 `Answer.text/evidence/coverage`。范围或问题变化后清空旧回答，迟到的旧响应不会混入新范围；无匹配资料时展示服务实际返回的结果。                                                                      |
| 设置与模板 | 服务、模板、完整备份和阅读偏好位于设置页。复用 `settings.save/test/testVision`、`template.save/delete`、项目默认值和完整库 `backup/restore`；密钥保存后清空输入框。备份恢复成功后重置导航上下文并显示恢复后的会议库。                                                         |

样式分为交付包的完整设计样式 `design-system.css`、保留功能布局并绑定设计变量的 `component-styles.css`，以及 React 布局接入层 `integration.css`。原三栏框架样式已替换。六个颜色变量和字体栈沿用设计基线；没有引入原型脚本、固定问答、演示会议或第二套业务存储。

阅读偏好单独使用 `meeting-recorder:reading-v1` 保存两个布尔值：正文大小、默认是否展开原文栏。它只保存此设备的界面偏好，不保存会议、项目、媒体、回答或密钥，也不改变完整库备份语义。

## 已保留的能力差异

1. 正式项目记录为只读详情，保留负责人、期限、状态、来源和变更历史。当前没有 `record.update`；界面不显示可假保存的编辑表单。
2. 确认提案时展示分析中的真实负责人、期限及引用，不允许在确认弹窗直接改写；`proposal.accept` 仍只接收既有三个定位字段。未明确的信息不会自动补造。
3. 新增正式记录编辑能力应另行立项，明确 typed IPC、校验、事务、历史、版本冲突与证据规则，并补充业务测试；本次未扩展这些权限。
4. 设置保留项目原有的独立图片模型、发送许可、输出预算和 Qwen 思考模式。模板保留内置只读、复制、自定义编辑及删除能力。录制、原始文件、历史分析等未在原型中完全演示的能力仍可达。

## 验证

所有验证使用独立临时库和明确标注的合成资料。本次没有读取或上传工作区中的真实会议录像，没有运行历史真实服务验证脚本。

| 检查                   | 结果                                                |
| ---------------------- | --------------------------------------------------- |
| 交付包校验             | 18 个文件哈希一致，5 页及页面引用完整               |
| `npm run format:check` | 通过                                                |
| `npm run build`        | TypeScript、Vite 与 Electron 构建通过               |
| `npm test`             | 54 项通过                                           |
| `npm run test:e2e`     | 15 项通过；会议信息默认项目修复后，相关回归另行通过 |
| `git diff --check`     | 通过                                                |

新增 Electron 检查覆盖：多项目和未归入项目筛选、空搜索、123 段原文分页与完整保存、原文版本引用、跨页时间定位、递归纪要、切换会议／分析清除旧引用、确认同类型的多个独立建议、只读历史、问答真实范围及日期、Markdown／SRT 导出、完整备份恢复及导航清理、阅读偏好持久化、弹窗焦点返回和 1440／1050／800／640 像素窗口下的溢出检查。

现有 Electron 回归继续覆盖合成麦克风的 WAV 保存、暂停继续、说话人统一、真实 FFmpeg 录像处理、关键画面参数、历史画面引用、录屏窗口选择、窗口关闭自动保存、强制进程终止恢复与保存后退出。说话人测试的文本定位限定到编辑区，分析确认测试增加新核对弹窗步骤，未删减原业务断言。

未验证：物理麦克风和真实会议软件的设备组合、长时间连续录制、真实 VibeVoice／模型服务的质量与性能、macOS 实机、超大会议库的全量 `state` 读取性能。Windows 录屏回归使用合成测试窗口；模型交互使用本机测试 HTTP 服务，不能据此宣称真实模型质量通过。未修改 Python，因此未重跑 Python 服务检查。
